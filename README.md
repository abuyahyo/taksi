# 🚕 Manzil — нархни ўзингиз белгилайдиган такси дастури

Веб-дастур: йўловчи нархни ўзи таклиф қилади, ҳайдовчилар рози бўлади ёки ўз нархини беради. Дастурнинг ўзига хос томони — **бошқа иловалардаги камчиликлар ечилган** ва уларда йўқ функциялар қўшилган.

## Тузилиши

```
taxi-app/
├── backend/    # Node.js + Express + Socket.io + PostgreSQL
└── frontend/   # React + Vite + Leaflet харита
```

## Ишга тушириш

### 1. Backend
```bash
cd backend
npm install
createdb taxi_app
psql -d taxi_app -f src/config/schema.sql
cp .env.example .env   # маълумотларни ўзгартиринг
npm run dev            # http://localhost:5000
```

### 2. Frontend (янги терминалда)
```bash
cd frontend
npm install
npm run dev            # http://localhost:5173
```

## Барқарор публик URL (картасиз)

**Муҳим:** backend frontend build'ни **бир origin**'да беради (`frontend/dist` → static + SPA fallback),
api.js ҳам production'да same-origin ишлатади. Шунинг учун тоннел URL ўзгарса ҳам
**илова синмайди** — фақат публик ҳавола янги бўлади. Илова тўлиқ ишлаши учун:
аввал `cd frontend && npm run build`, кейин backend'ни ишга туширинг (у dist'ни беради),
сўнг тоннелни **5000-портга** қаратинг (5173 эмас).

Тоннел вариантлари:
- **Cloudflare quick tunnel** — `cloudflared tunnel --url http://localhost:5000`.
  Бепул, картасиз, лекин URL **ҳар сафар ўзгаради**.
- **ngrok бепул статик домен** — URL **барқарор** (ҳар рестартда бир хил), карта **керак эмас**.
  1. https://dashboard.ngrok.com/domains — 1 та текин домен олинг (масалан `sizniki.ngrok-free.app`).
  2. `ngrok http 5000 --domain sizniki.ngrok-free.app`
  3. Шу ҳаволани ҳайдовчи/йўловчиларга тарқатинг — у ўзгармайди.

### Битта буйруқ билан (start.ps1)
Repo илдизида `start.ps1` бор — frontend build + backend + тоннелни кетма-кет ишга туширади:
```powershell
.\start.ps1                                          # cloudflared (ўзгарувчан URL)
$env:NGROK_DOMAIN="sizniki.ngrok-free.app"; .\start.ps1   # ngrok (барқарор URL)
```

## ⚖️ Шаффоф блоклаш — биз ўйлаб топдик

**Муаммо:** Бошқа иловаларда блокланган фойдаланувчига **сабаб айтилмайди**. У "Аккаунт заблокирован" хабарини олади, ҳолос. Қўллаб-қувватловчига ёзади, 2-3 кун жавоб кутади, кўпинча "siyosatga zid" каби умумий жавоб. Бу:

- Фойдаланувчи нима учун жазоланганини билмайди → тузатилолмайди
- Адолатсиз бўлса исбот қилолмайди
- Жанжалга ва рақибга ўтиб кетишга олиб келади

**Бизнинг ечим — техник архитектурада маҳкам:**

1. Админ блок қилмоқчи бўлса, **сабаб мажбурий** (UI'да ва backend'да). Сабабсиз тасдиқлаш техник жиҳатдан имконсиз:

   ```js
   if (!sabab) {
     return res.status(400).json({ xato: 'Блоклаш сабабини кўрсатинг' });
   }
   ```

2. Блокланган фойдаланувчи login қилгач, **сабабни ўзи кўради**:

   ```
   ❌ Ҳисобингиз блокланган (Кўп бекор қилиш — 7 кун ичида 12 марта)
   ```

3. База жадвалида ҳам сабаб ва вақт сақланади (`blok_sababi`, `blok_vaqti`) — кейинги аудит учун.

**Натижа:**
- Фойдаланувчи нимани тузатишни **аниқ билади**
- Кейинги марта шу хатони қилмайди
- Адолатсиз бўлса, аниқ далил билан шикоят қилади
- Платформага ишонч ошади

Бу ечим бошқа иловаларда йўқ. **Manzil'нинг ўзига хос тамойили — шаффоф адолат.**
